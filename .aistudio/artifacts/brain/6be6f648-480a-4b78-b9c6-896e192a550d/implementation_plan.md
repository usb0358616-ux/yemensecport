# خطة بناء وتصميم: نظام المنافذ والجوازات الذكي

نظام مكتبي متكامل لإدارة المنافذ الحدودية ونقاط الجوازات، يشمل التحقق الأمني المتقدم من المسافرين، بلاغات الضبط، تتبع حركة الأطقم، والتقارير التحليلية، مصمم ليعمل بكفاءة دون اتصال بالإنترنت (Offline-First) كبرنامج تنفيذي على أنظمة Windows.

---

## مراجعة المستخدم والقرارات الاستراتيجية

> [!IMPORTANT]
> يرجى مراجعة الخطة والخيارات التصميمية التالية وتأكيدها للمضي قدماً في أي تحسينات أو إضافات قادمة:

- **طبيعة التشغيل والمزامنة**: النظام يعمل بنمط **Offline-First** بالكامل (تخزين محلي LocalStorage / IndexedDB / SQLite محلي)، مع إمكانية التصدير والاستيراد اليدوي لملفات النسخ الاحتياطي (JSON / Excel)، بالإضافة إلى دعم بوابة المزامنة الاختيارية (Google Workspace) عند توفر الاتصال.
- **التوافق المكتبي (Windows Desktop)**: ضمان حزم التطبيق محلياً بصيغة ملف تنفيذي (.exe) بدون أي اعتماديات على شبكات التوزيع السحابية (CDNs)، بحيث تكون الخطوط والأيقونات مدمجة 100%.
- **الأمان والتحقق الأمني الرباعي**: تدقيق فوري للأسماء وأرقام الهويات ومطابقتها التلقائية مع قاعدة بلاغات الضبط والممنوعين من السفر عند إدخال بيانات أي مسافر.

---

## 1. نظرة عامة والمفهوم الجوهري (Overview & Core Concept)

### الغرض الأساسي
توفير منصة إلكترونية سريعة وموثوقة لضباط المنافذ ومدخلي البيانات لمراقبة وإدارة تدفق المسافرين والمركبات الأمنية، وتسجيل المعاينات والتدقيق الأمني في غضون ثوانٍ لمنع عبور المطلوبين وتسهيل حركة المرور النظامية.

### الفئات المستهدفة
1. **ضابط المنفذ / التحقيق**: مسؤول المعاينة الأمنية، اتخاذ قرار السماح أو الرفض، وإصدار بلاغات الضبط.
2. **مدخل البيانات**: تسجيل بيانات المسافرين والوثائق وحركة الدوريات اليومية.
3. **مدير المنفذ (الآدمن)**: الاطلاع على الإحصائيات الحية، إدارة حسابات المستخدمين، النسخ الاحتياطي، وإعدادات النظام.

### القيمة التشغيلية
- القضاء على الإجراءات الورقية وتقليص وقت إنهاء إجراءات المسافر لأقل من دقيقة.
- كشف فوري ومطابقة ذكية للمطلوبين أمنياً وحالات المنع من السفر.
- ضمان استمرارية العمل على مدار الساعة دون الحاجة لأي اتصال بالإنترنت.

## 2. تجربة المستخدم والتصميم البصري (UX & Visual Design)

### تدفقات المستخدم الرئيسية (Key User Flows)

1. **تدفق تسجيل وتدقيق المسافر (Traveler Inspection Flow)**:
   - فتح شاشة المسافرين ← إدخال الاسم الرباعي ورقم الهوية/الجواز ← إجراء الفحص الأمني التلقائي (Vetting Checks 1-4) مقابل بلاغات الضبط.
   - إذا وجد تطابق: ظهور تنبيه أمني فوري عالي الأهمية (High-Priority Alert) مع خيار منع السفر وربط البلاغ.
   - إذا كانت السجلات سليمة: اعتماد نتيجة الفحص وطباعة كارت أو إيصال المعاينة.

2. **تدفق حركة الأطقم والدوريات (Patrol & Crew Movements)**:
   - تسجيل خروج طقم/مركبة (رقم اللوحة، السائق، الأفراد، المهمة، وقت المغادرة والمتوقع).
   - تتبع الحالات الحية (في الميدان / عادت) مع توثيق وقت العودة الفعلي والنتائج.

3. **تدفق بلاغات الضبط والمطلوبين (Wanted Persons & Security Alerts)**:
   - إنشاء بلاغ ضبط جديد ببيانات الهوية والسبب والمرفقات.
   - إمكانية التصفية بحسب الحالة (جديد، قيد التحقيق، معتمد، مغلق) ومتابعة الإجراءات المتخذة.

4. **لوحة الإحصائيات والمؤشرات (Statistics & Analytics)**:
   - مؤشرات لحظية (KPIs): إجمالي المسافرين، نسبة المسموح لهم مقابل الممنوعين، حركات الأطقم النشطة، والبيانات البيانية للوجهات والجنسيات.

### الهوية البصرية ونظام التصميم (Visual Identity & Design System)

```
┌────────────────────────────────────────────────────────────────────────┐
│                        الواجهة العامة (RTL Arabic)                     │
├───────────────────┬────────────────────────────────────────────────────┤
│ شريط التنقل الأيمن │ منطقة العمل الرئيسية (Main Content Area)           │
│  - المسافرين      │  [بطاقات الإحصائيات العلوية KPI Cards]              │
│  - حركة الأطقم    ├────────────────────────────────────────────────────┤
│  - بلاغات الضبط   │  [شريط البحث المتقدم + أزرار التصفية والإضافة]    │
│  - الإحصائيات     ├────────────────────────────────────────────────────┤
│  - الإعدادات      │  [جدول البيانات التفاعلي مع علامات الحالة Badge]   │
└───────────────────┴────────────────────────────────────────────────────┘
```

- **الاتجاه واللغة**: تصميم موجه بالكامل للغة العربية من اليمين لليسار (RTL) مع خطوط محلية متناسقة وواضحة (Cairo / Inter / خطوط النظام المحلية عالية القراءة).
- **لوحة الألوان المستوحاة من الأنظمة الحكومية والسيادية**:
  - **اللون الأساسي (Primary)**: كحلي داكن أمني `#1e293b` و `#0f172a` يعكس الرصانة والموثوقية.
  - **لون التأكيد والتمييز (Accent)**: الزمردي الأخضر `#10b981` (للمسموح والعمليات المكتملة) والأزرق الملكي `#2563eb` للأزرار التفاعلية.
  - **ألوان التنبيه والحالات الأمنية (Status Tokens)**:
    - أحمر قاني `#ef4444`: المنع من السفر / مطلوب أمنياً / خطر.
    - كهرماني `#f59e0b`: قيد التحقيق / حركة معلقة.
    - رمادي حيادي `#64748b` وخلفية `#f8fafc`: لتقليل إجهاد العين أثناء العمل لفترات طويلة.
- **عناصر الواجهة (Components)**:
  - استخدام بطاقات shadcn/ui المهندسة، جداول بيانات تفاعلية مع فرز وترقيم صفحات، نوافذ حوارية (Modals/Dialogs) واضحة وغير مزدحمة، ونظام إشعارات Sonner Toast سريع الاستجابة.

## 3. القرارات التقنية والمفاضلات (Key Decisions & Trade-Offs)

| القرار الهندسي | الخيار المعتمد | السبب والميزة التشغيلية | البدائل التي تم استبعادها |
| :--- | :--- | :--- | :--- |
| **بيئة التشغيل** | نمط مكتبي محلي مستقل (Offline-first Windows App) | المنفذ قد يتعرض لانقطاع شبكة أو لا يملك اتصال إنترنت دائم؛ البيانات تبقى على الجهاز بأمان. | الاعتماد الإجباري على خادم سحابي خارجي |
| **تخزين البيانات** | تخزين محلي منظم (LocalStorage + Structured Repository) مع تصدير/استيراد JSON مشفر | تشغيل فوري بدون الحاجة لتثبيت محركات قواعد بيانات ثقيلة على أجهزة العميل الضعيفة، مع سهولة النقل. | إجبار تثبيت سيرفر PostgreSQL أو خوادم معقدة للتشغيل الفردي |
| **الخطوط والأيقونات** | أصول مدمجة محلياً (Bundled Lucide Icons & System Fonts) | الالتزام الصارم بتعليمات بيئة Windows دون اتصال؛ منع أي استدعاء خارجي من Google Fonts أو CDNs. | الروابط السحابية مثل cdnjs أو unpkg |
| **المزامنة الخارجية** | بوابة تصدير واستيراد مرنة + تكامل Google Workspace اختياري | منح المرونة للإدارة لنقل البيانات عند توفر نقطة اتصال دون تعطيل سير العمل اليومي إذا فُقد الاتصال. | المزامنة الحية المتطلبة لاتصال دائم |

## 4. الهيكلية البرمجية واستراتيجية البيانات (Technical Architecture)

### مخطط تدفق البيانات ومكونات النظام

```
┌────────────────────────────────────────────────────────────────────────┐
│                        واجهة المستخدم (React + TS)                     │

│   └───────┬──────┘   └───────┬───────┘   └────────────┬────────────┘   │
└───────────┼──────────────────┼────────────────────────┼────────────────┘
            │                  │                        │
            ▼                  ▼                        ▼
┌────────────────────────────────────────────────────────────────────────┐
│                        طبقة الخدمات وإدارة الحالة                      │
│   - التحقق الأمني التلقائي (Cross-check Vetting Engine)                │
│   - محرك البحث السريع والتصفية (Client-side Search & Filters)          │
│   - محرك التصدير والطباعة (PDF/Excel/JSON Exporters)                   │
└──────────────────────────────────┬─────────────────────────────────────┘
                                   │
                                   ▼
┌────────────────────────────────────────────────────────────────────────┐
│                     طبقة التخزين المحلي (Local Storage)                │
│   - جدول المسافرين (Travelers Store)                                    │
│   - جدول البلاغات الأمنية (Reports & Watchlist Store)                   │
│   - جدول الحركات والدوريات (Movements Store)                           │
│   - جدول المستخدمين والصلاحيات (Users & Roles)                          │
└────────────────────────────────────────────────────────────────────────┘
```

### الكيانات الأساسية (Data Models)
1. **Traveler (المسافر)**:
   - المعرف، الاسم الخماسي، رقم الهوية، نوعها، الدولة، المحافظة، الهاتف.
   - نتائج المعاينة الأمنية (Vetting Results 1-4)، الوجهة، سبب الزيارة، الضابط المعاين.
   - حالة السفر (مسموح / ممنوع)، سبب الإرجاع إن وجد، الصور والمستندات، والبلاغات المرتبطة.
2. **Report (بلاغ الضبط)**:
   - المعرف، العنوان، التفاصيل، النوع، الحالة (جديد، قيد التحقيق، معتمد، مرفوض)، والمرفقات والمسافرين المرتبطين.
3. **Movement (حركة الأطقم)**:
   - المعرف، نوع المركبة، رقم اللوحة، اسم السائق، عدد الأفراد، المهمة، أوقات الخروج والعودة، والنتيجة.
4. **User & Auth (المستخدمين)**:
   - المعرف، اسم المستخدم، الدور (آدمن، ضابط، مدخل بيانات)، الاسم الكامل.

## 5. خطة التنفيذ والتحسينات المستقبلية الموصى بها

1. **المرحلة 1: التدقيق والأمان**
   - تعزيز محرك التنبيه الفوري بمجرد إدخال هوية مسافر موجود في بلاغات الضبط.
   - إضافة تدقيق تشابه الأسماء (Soundex / Fuzzy Search) للأسماء المشبوهة.
2. **المرحلة 2: واجهة المستخدم والتقارير**
   - تصميم قوالب طباعة متوافقة مع ورق A4 وطابعات الإيصالات الحرارية (POS/Receipt printers) لبطاقات المعاينة.
   - تحسين رسوم البيانية الإحصائية لتشمل التوزيع الجغرافي والزمني لحركة المنفذ.
3. **المرحلة 3: النسخ الاحتياطي وحزم Windows**
   - إعداد ميزة النسخ الاحتياطي الآلي الدوري بملف واحد مضغوط أو مشفر محلياً.
   - توفير ملفات الإعداد الخاصة بـ Electron / Tauri لتحويل التطبيق مباشرة إلى ملف تنفيذي `.exe` يعمل على Windows دون متصفح خارجي.
